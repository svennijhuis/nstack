# Spec

Where the decisions sit, by the skill that wrote the spec. They outrank your own shape choices.

| Spec from | Decisions |
| --- | --- |
| `to-spec` | Implementation Decisions, Testing Decisions, and the seams it names |
| `tech-design` (`docs/design/<date>-<name>/design.md`) | Decisions so far; Design: Boundaries and contracts, Data model; Cross-cutting: Testing. Its `tickets.md` links each ticket to its section. |
| a parent issue | Its body and its decided comments |

The code fights the spec, or the spec leaves two equal shapes open: ask the person, one question with the options.
